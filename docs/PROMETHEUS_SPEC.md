# PROMETHEUS — Advanced Character Motion Laboratory

Operation 04 extends the HUMAN skeleton and the existing executable world. Its scope is character movement, contact experiments, runtime retargeting and measurements. It adds no missions or expanded city map. Rendering and existing character ownership remain in place.

The production target remains modern **60+ CU-class, RT-capable GPUs**, with an original Indian setting and GTA VI/RDR2-level visual ambition. The local compatibility machine does not define the visual ceiling. The executable currently uses WebGL2 without hardware ray tracing. Neither this laboratory nor the operation count establishes final AAA visual or animation quality. The humans remain stylized procedural HUMAN assets.

## Runtime ownership and motion order

`Runtime` owns `MotionDirector`; the latter owns the removable `MotionLab`, physics ground sampler, context and interaction selection. `HumanSystem` owns a `MotionController` for the hero, each cast character and every instantiated nearby citizen. The existing twelve-rig streamed-character limit remains. Each cast retargeter captures its rest pose before animation.

The fixed-step Rapier controller remains authoritative over world translation. Context scales desired speed and acceleration. Achieved player displacement drives the visible hero, so movement input held against a wall does not justify continued walking. Facing turns toward travel at a bounded rate. Grounded state and vertical velocity drive jump/landing state.

Each pose retains HUMAN's face/finger layer, applies body/arm offsets, updates stance/swing targets, compensates the pelvis, solves legs, preserves planted foot orientation and applies hand contact. The prior nonuniform chest breathing scale is reset before IK; shear would violate the rigid segment assumption. Breathing is not a physical respiratory model.

Movement intervals are clamped and may be subdivided into bounded approximately 60 Hz steps during significant displacement. This protects contact progression at coarse render cadence. It does not establish complete skeleton/render interpolation. Tier 1 retains a higher requested pose frequency than tier 2; far instances remain static simplified HUMAN representations.

## Bone, coordinate and retargeting contract

HUMAN has 51 named bones, uses metres, +Y up and +Z forward, and has a feet-origin root. The parent mesh/group places the avatar in the scene; skeletal root translation is separate.

| Contact chain   | Direct bone chain                                 |
| --------------- | ------------------------------------------------- |
| `armL` / `armR` | `upperArm` → `forearm` → `hand`, with side suffix |
| `legL` / `legR` | `thigh` → `shin` → `ankle`, with side suffix      |

Twist bones are helper branches, not intermediate IK joints. Local translations define segment lengths and remain unchanged by positional solving. The caller supplies endpoint orientation and any further contact or anatomical constraints.

`createRetargeter(sourceRig, targetRig, options)` captures rest poses immediately; construct it before animation. `options.map` is one-to-one source-name → target-name and validates mapped parent relationships. Rest orientations correct different local joint axes in the common avatar frame. Explicit `sourceHeight`/`targetHeight` supply root scaling; the known HUMAN rig can infer height from its head convention. Imported rigs should supply measured heights and maps.

`apply({ rootMotion, contacts })` transfers rest-relative quaternion deltas, scales root translation by target/source height, and solves contacts afterward. It does not scale bone lengths or scene placement. Contact targets are **world positions**. Transform object-local attachments before solving them. The current box target follows translation; arbitrary rotating grasp frames and target orientation are not established.

A short and a tall character reaching the same physical handle must arrive at the same world point. Their shoulder location, elbow bend, pelvis adjustment and local hand position differ. Reusing a fixed local hand height would miss the object. Tests measure actual endpoints and distinct joint placements.

`solveTwoBone` returns success, reachability, clamping, requested distance, measured lengths, achieved endpoint, clamped target and actual error against the original target. Degenerate poles get a deterministic fallback. Malformed chains, non-finite targets and nonuniform/mirrored transforms fail explicitly. Positional reach does not enforce realistic joint ranges or prevent torso intersection.

## Ground and support contract

The runtime sampler casts downward from 0.65 m above the supplied foot reference over 1.5 m. It excludes the player, sensors and standalone citizen contacts; surfaces with upward normal component below 0.45 are rejected. Height, normal and collider handle come from physics geometry. Rapier documents ray-hit normals and filters for excluding characters and sensors. [Rapier scene-query documentation](https://rapier.rs/docs/user_guides/javascript/scene_queries/).

Stance feet retain world X/Z and resample height/normal. Ankle targets use the HUMAN height-dependent support offset. Swing feet follow an interpolated clearance arc. A pivot can reposition one foot while the other supports. Airborne motion releases contacts; supported landing reacquires them; teleports clear previous anchors.

This is principally a **static-support experiment**. Feet are not attached to collider-local frames. Height resampling may follow vertical change, but horizontal or rotating platform support is not preserved. A single ray cannot determine whole-sole support, heel/toe clearance or a robust response to every missing hit. Missing queries and reach residuals must remain visible. Bounded pelvis correction cannot repair every target/body/terrain configuration.

## Laboratory and interactions

The removable 20 × 24 m elevated platform remains inside existing world bounds. It has flat ground, eight 18 cm stair rises, an 18 cm curb, a roughly 14-degree slope, uneven paving, a 1.2 m doorway, wall, chair, car-door handle fixture, scooter/rickshaw seats and grips, movable box and shallow puddle sensor. These are dimensioned physics fixtures, not finished city or vehicle assets.

When active, the lab owns 34 rigid bodies/colliders, including one dynamic box and one puddle sensor, one shared geometry and five materials. Entry is idempotent. Exit releases its physics/graphics resources and restores the outside player position. Lab state is temporary and world saving is disabled inside it; original streaming/player ownership remains unchanged.

The UI supports entry/exit, course selection, target alignment, context styles, body comparison, contact release and motion validation. Station/contact selection uses an explicit test teleport/alignment, not a naturally selected approach animation. Seat/vehicle selectors expose incomplete experiments; full seat contact, entry and two-handed steering require additional implementation.

## Validation and measurement

Focused tests inspect real endpoints, invariant lengths, clamp errors, rest axes, root scaling and rejected inputs. Controller tests retain actual stance anchors across heights, movement cadences, pivots, jump/landing, teleports and hand release. Lab tests inspect collider heights/normals, traversal, the moving box and repeated resource release. Engineering error thresholds are not biomechanical quality certification.

The browser harness exercises fixtures, support/airborne state, courses, hand reach, body comparison and resource recovery. Source code alone does not establish a passed executable run. Final pass/fail results and performance conditions are recorded separately in the integration evidence.

Telemetry includes state/transitions, steps, contacts, actual ankle-to-target error, target motion, ankle motion, missing samples, hand error/reachability, pelvis offset, speed, predicted endpoint, active rigs and HUMAN CPU cost. `footActualSlide` is per solver step, not automatically the maximum over a whole walk; tests additionally retain stance anchors to measure accumulated drift. Existing FPS, frame time, render passes, draw/triangle counts, bodies, cells and memory remain available. No target-GPU performance is inferred from a test threshold.
