# System status — PHOTON 0.2, 2026-09-12

Operation 02 builds on canonical GENESIS `43114ceaaaf0eb5e82df5749fba5beb93f4c8dcd`. This is the original Navapur rendering laboratory integrated with the existing playable district. No later operation, story expansion or map expansion was launched. Use this milestone's Git commit for exact source identity.

The user's production target is modern hardware in the **60+ compute-unit class with ray-tracing capabilities**. The local Intel HD 2000 is a compatibility/correctness test machine, not the intended quality ceiling. This backend is WebGL2; owning an RT-capable GPU does not make hardware ray tracing available in this implementation. Performance acceptance on a specified modern GPU/resolution remains unmeasured.

## Verification and measured results

- Final gameplay browser regression: **11/11 passed**. Movement 4.12 m, jump 0.75 m, wall stop 11.65 m before 11.99 m wall, 101 cells created/76 evicted, 25 resident cells, 226 rigid bodies and 36 geometries after traversal. See [gameplay evidence](evidence/photon-gameplay-regression.json).
- Manual final controls: three W presses moved z=8.0 to z=7.6; Save, Return to plaza and Load restored z=7.6 with 25 resident cells and 226 bodies. Reference Night and Rain were visually inspected; see [inspection notes](evidence/photon-visual-inspection.md).
- Browser console: no captured errors; existing nonfatal upstream Rapier initialization deprecation warning.
- Code regression: **26/26 tests passed**, including the seven GENESIS tests, fifteen-category LOD/error policy, material/resource lifetime, PBO transfer/error recovery and probe shadow-state restoration.
- Production build passed: 38 modules; app 81.23 kB, rendering 491.36 kB, physics/WASM 2,216.11 kB before gzip. The existing physics bundle size warning remains.
- The first production rendering comparison passed **8/8 checks**, with four actual configurations. See [pre-fix evidence](evidence/photon-before-readback-fix.json). It exposed synchronous pixel-read stalls, which were then replaced by nonblocking PBO/fence readback.
- Final production rendering comparison: **8/8 passed**, including PBO/fence metering with no reported error. See [PHOTON comparison](evidence/photon-comparison.json). Final viewport was larger: 972×814 Balanced, 800×670 Performance, 1144×958 Reference. Corresponding FPS: 6.39 without planar, 6.29 with planar, 9.03 Rain/Performance, 2.35 Night/Reference. These are compatibility measurements, not a matched speedup comparison or production acceptance.

Earlier hardware observation: ANGLE / Mesa Intel HD Graphics 2000 (SNB GT1), OpenGL 3.3, WebGL2, real HDR framebuffer and GPU timer queries; WebGPU adapter request returned null. Four-second fixed-camera windows before the readback repair produced 15.31 FPS Balanced without planar, 14.34 FPS Balanced with planar, 20.75 FPS Rain/Performance, and 4.67 FPS Night/Reference. These are local observations, not modern-GPU acceptance results. The Reference path remained enabled and was tested despite this machine's speed.

Counts include 25 resident cells, 100 NPC proxies, 50 vehicle proxies and 226 rigid bodies. Repeated quality/probe cycles after warming Reference held at 20 texture and 36 geometry allocations. These allocation counts are not a VRAM measurement. Draw/triangle counters include extra render passes and vary on capture frames.

## Fixes, artifacts and recovery

PHOTON fixes include explicit renderer/runtime disposal ownership, sun shadow-map disposal, context-listener cleanup, disjoint GPU query cleanup, failed-probe state restoration, current-shadow refresh on the first cube face, probe capture gated by its own resident cell, physical puddle fallback when culled, camera matrix updates before reflection culling, sky recentering, shared-base rain wrapping, inspection-mode player anchoring and isolated validation controls. The asynchronous meter removes the explicit synchronous pixel/fence wait and completed samples without errors in the production browser. Driver/command submission still stalled heavily (latest meter CPU submissions 348–1250 ms in the larger final viewport); no net speedup is claimed. A modern-GPU profile is needed before selecting further repairs.

Remaining rendering artifacts: stale dynamic objects in the snapshot probe; plaza IBL applied to distant world materials; box correction rather than actual geometry; planar lag/stretching at rapid motion; transparent-depth fog/AO artifacts; alpha/transmission sorting; single-shadow coverage and shimmer; microtexture repetition; approximate AA, bloom and AO. Skin sheen is not subsurface scattering; an anisotropic cap is not strand hair. The lab is render-only and moving GENESIS traffic proxies can cross its display objects.

Inherited limits: generic procedural blockout, no final regional assets; cross-cell moved-prop registry incomplete; 2048-record persistence cap; hard ±2048 m region bound; camera smoothing near walls; no worker timeout/retry or long-duration soak; no actual driving, police, combat, missions or audio. Large WASM payload affects startup. Save/Load is local to the browser origin, so localhost and 127.0.0.1 have separate storage.

Recover with `npm ci`, `npm test`, `npm run build`, `npm run preview`. Use **Compare rendering**, **Run diagnostics**, and **Export metrics**. Reload after a graphics-context loss. Local server restart may need the host's port permission. During this run browser-control timeouts coincided with a 3.6 GB RAM host using about 2.5 GB swap and high system load; this is recorded as an environment observation, not a proven renderer failure. No paid compute, generation service or remote deployment was used.
