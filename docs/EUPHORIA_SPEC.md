# EUPHORIA INDIA — physical character reactions

Operation 05 extends the committed PROMETHEUS motion architecture. The operation name is a project label: this is original physical-animation code using Rapier, not NaturalMotion's proprietary Euphoria engine, a neural controller or a motion-capture system. Existing movement, identity, streaming, rendering and procedural animation remain available.

The production target remains an original Indian game with GTA VI/RDR2-level visual ambition on modern **60+ CU-class, RT-capable GPUs**. The local machine is a compatibility device, not the visual ceiling. Current WebGL2 execution has no hardware RT. This operation includes a concrete character-surface improvement, but neither the physical subsystem nor the revised procedural art establishes final AAA quality.

## Ownership and control modes

`Runtime` owns `PhysicalReactions`, which owns one transient hero `Articulation`, a `BalanceController`, `WallBrace`, reaction history and recovery state. The articulation owns its thirteen bodies/colliders and twelve impulse joints. The wall brace owns at most one additional joint and is released before its articulation. Physical state is temporary and is not serialized into world saves.

Ordinary movement remains the PROMETHEUS Rapier character controller. A reaction starts from the current animated world pose. During partial mode, only the pelvis is kinematic; captured pose targets follow controller displacement at fixed-step cadence, while torso/limbs receive real impulses and torques. The controller's horizontal response to a push is a deliberately tuned external-velocity contribution, not an independently simulated free-body root.

After `Articulation.sync`, grounded partial mode solves each initialized leg analytically back to its current PROMETHEUS stance or swing target and restores its support-normal orientation. This final visual correction preserves the intended planted or lifted foot path instead of allowing the physical rotation blend to erase it. The corresponding dynamic leg/foot colliders are not repositioned by this correction, so they can deviate from the visible legs. This is an explicit hybrid of controller support, simulated reaction links and corrected visual contact. Full falls retain the physical leg mapping without this final correction.

Full mode disables the original player collider and releases the pelvis. All thirteen links then simulate dynamically. Pre-impact travel velocity is carried into the fall. The disabled capsule's position may follow the physical pelvis for camera/streaming, but it contributes no collision force. `Articulation.sync(weight)` preserves the visual group transform, maps actual physical orientations and changes the skeletal pelvis translation in full mode. Active rendering keeps the mesh from being culled solely by its original standing bounds.

Pose capture occurs after the underlying procedural pose and protective offsets, before physics-to-animation blending. Capture must not read the previously blended physical pose as its new animation target. At partial completion, physical influence fades; full recovery selects a clear standing capsule location and blends to the underlying motion pose. The controller then resumes ownership. Collision clearance is checked again before completion. A new impact during full recovery cancels that recovery rather than finishing on an obsolete timer.

Recovery still has important limits: standing placement is selected from a bounded set of local samples; a clear final capsule does not prove that every interpolated limb is clear. The visual get-up is a pose blend with controller placement, not muscle-driven rising. If no suitable placement is found, recovery remains blocked for another attempt. Configuration/reset cleanup restores an appropriate controller location and releases transient resources.

## Physical model and units

Units are metres, seconds, kilograms, radians, N·s for linear impulse and N·m·s for angular impulse. The existing fixed timestep is 1/60 s and gravity is −18 m/s² on Y. That gravity, reaction thresholds, drive gains and surface coefficients are gameplay DESIGN CHOICES, not biomechanical measurements.

| Link allocation          | Fraction of configured mass |
| ------------------------ | --------------------------- |
| Pelvis                   | 0.18                        |
| Chest                    | 0.32                        |
| Head                     | 0.08                        |
| Each upper arm / forearm | 0.035 / 0.025               |
| Each thigh / shin / foot | 0.10 / 0.035 / 0.015        |

Fractions total 1.0. UI experiments bound configured mass to 45–120 kg and friction to 0.12–1; the reusable articulation accepts positive finite mass and nonnegative finite friction. Collider dimensions derive from current HUMAN proportions. Rapier computes inertia from collider geometry/mass. Linear damping is 0.12, angular damping 0.3 and restitution 0.02; CCD and additional solver iterations improve bounded test stability. These values are tuning parameters.

Four hinges constrain elbows/knees with activation-relative angular ranges. The remaining spherical joints constrain relative anchor translation without anatomical cone/twist limits. The reference is the activation pose, not a calibrated anatomical neutral pose. Bodies require finite unit-scale transforms. The existing nonuniform chest breathing scale must be reset before activation.

The physical `chest` link maps to `spine`, `head` maps to `neck`, and feet map to `ankleL/R`. Intervening chest/head rotations retain their activation-local orientation so mapping does not pop the body into a rest pose. Unchanged skeletal translations preserve visual limb lengths. The skeleton's 51 bones therefore remain distinct from its thirteen physical links.

Collision membership 2/filter 1 suppresses articulation self-contact. It also suppresses contact between articulations using that same group convention; this is not a multi-body crowd contact solution. An optionally excluded player collider has its previous filter restored on disposal. Ground queries exclude the reaction's own colliders so they cannot become animation support surfaces.

## Drives and balance policy

Each internal drive compares a desired parent-relative quaternion with the actual parent/child orientations. A shortest-angle error and relative angular velocity produce a PD torque, bounded using the child's mass fraction. Torque is applied as a timestep-scaled impulse to the child and with opposite sign to its dynamic parent. Thus the unanchored drive does not inject a net external upright torque. The kinematic pelvis provides an explicit external boundary in partial mode. Rapier's joint definitions distinguish spherical translational constraints from one-axis revolute motion; this implementation uses custom bounded torque impulses rather than claiming unavailable motor APIs. [Rapier joints](https://rapier.rs/docs/user_guides/javascript/joints/).

The balance estimator computes a convex support hull from supplied points. In the current integration, these are estimated rectangular patches around retained PROMETHEUS foot anchors, not pressure-sensed sole polygons. For effective COM height `h`, it computes `omega = sqrt(g/h)` and horizontal capture point `COM + velocity/omega`. It also estimates stopping distance from speed and friction. The constant-height inverted-pendulum capture-point model is a simplified robotics tool; the original research explicitly distinguishes it from general humanoid dynamics and from angular-momentum flywheel extensions. [Pratt et al., Capture Point: A Step toward Humanoid Push Recovery](https://www.cs.cmu.edu/~cga/legs/Pratt_Goswami_Humanoids2006.pdf).

The policy exposes balanced, correcting, stepping, falling and recovering states; thresholds account for impulse, direction, effective support, friction and stance. Lean and brace values influence procedural targets. For a grounded partial reaction with impulse magnitude/mass above 0.9 N·s/kg, the integration can call `MotionController.requestRecoveryStep` with the policy's `stepDirection` and `stepDistance`. One accepted recovery step is requested per episode during its initial 1.8 s. The policy target therefore has an executable consumer; it is still not a whole-body optimization or physical stepping controller.

`requestRecoveryStep` requires two initialized, locked feet and no active interaction. It chooses the foot on the disturbance side, retains the other as support, bounds requested horizontal distance to 0.1 m through 0.22 times body height, and checks the destination against actual ground. It rejects missing/nonfinite heights, normal Y below 0.65, excessive height change or a target farther than half the body height from the existing foot point. An accepted request creates a 0.24 s swing with a clearance arc and then reacquires stance. The actual rendered ankle after all physical mapping must be measured; incrementing the step counter alone is insufficient. In partial mode the root remains supported by the controller, so apparent successful balance is not evidence of a free dynamic biped.

`WallBrace` accepts only nearby fixed nonsensor wall geometry. Runtime attempts a catch from bracing feedback and the character's forward direction. The requested point must be on the collider surface and within 0.12 m of the forearm endpoint proxy. A spherical constraint can briefly pull that proxy toward contact; excessive 0.25 m anchor error, support removal, disabling or a 0.6 s timeout releases it. Horizontal surfaces are rejected. This bounded helper does not simulate a palm patch, finger force or sustained hanging. Runtime catch claims require live integration evidence.

## Scenarios, graphics and verification

Controlled scenarios distinguish a small bump, harder push, full collapse, motorcycle/car impact events and occupant deceleration. The event-transfer approximation uses both masses, closing speed and restitution to produce an impulse; it does not contain a vehicle collision simulation. State/source labels alone are never evidence of physical differentiation. Test actual displacement, link momentum, steps, contacts and release behavior.

The graphics increment uses continuous procedural cross-section profiles for near/hero garments and limbs, plus original woven normal and roughness textures. Existing skinning, morphs, materials and lower-detail representations remain compatible. Cloth texture shading is not cloth simulation. This increment requires its own before/after visual evidence and resource checks; no percentage of GTA VI/RDR2 quality is inferred.

Articulation tests observe actual masses/inertia, impulse response, equal/opposite drive accounting, dynamic release, joint anchors, multiple stair colliders, inherited-pose alignment and exact lifetime restoration. Integration tests additionally exercise partial/full mode, controller coupling, recovery and repeated impacts. An earlier integrated build passed 14/14 reaction, 8/8 HUMAN, 11/11 GENESIS and 8/8 PHOTON browser checks. Those passes predate the stronger recovery-step endpoint checks and do not certify the latest correction. The final corrected build passed 89/89 automated tests, 14/14 live reaction checks and 15/15 inherited live motion checks. See SYSTEM_STATUS and the build-specific evidence.

Telemetry separates measured physical COM/momentum/inertia/energy from the simplified policy's estimates. It exposes physical mode, link/joint counts, contacts and support normals, anchor errors, drive strength/torque, state, recovery status, CPU cost and existing render/memory counters. Energy may change through gravity, damping, external impulses, contacts, motor work and kinematic support. Record actual measurement conditions in evidence; do not infer high-end GPU results from local testing.

## Recovery-step failure and repair status

Additional checks at 6 Hz and 10 Hz motion/render cadence first exposed zero recovery footsteps. An explicit ground-checked step request repaired the missing request path, but inspecting the rendered ankle after the physical blend then exposed no actual foot lift and approximately 24 cm of sliding. The step target and counter could advance while physical mapping overwrote the intended foot motion.

The latest correction applies final analytic leg IK after physical synchronization only for grounded partial reactions, preserving both retained stance points and the requested swing. Full falls remain physically mapped. The correction passed actual ankle lift and planted-foot residual tests at 6/10 Hz pose cadence, plus the final live reaction and motion regressions; exact thresholds and measured results are recorded in evidence. Its visual/physical leg divergence is an explicit limitation, not a dynamically balanced free-biped solution.
